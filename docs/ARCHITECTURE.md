# 架构与维护边界

## 组件

| 层 | 位置 | 职责 |
| --- | --- | --- |
| Vue renderer | src | 创作界面、业务状态、路由与交互 |
| Electron main / preload | electron | IPC、文件、SQLite、音视频与服务商调用 |
| 独立后台 | user-server | 注册登录、设备、订阅、配额、服务商配置与管理界面 |
| 本地处理 | python、electron/resources/extra | FFmpeg、Python 与可选模型服务 |
| 配置与打包 | scripts、vite.config.ts、electron-builder.json5 | 启动、资源预检、构建和源码导出 |

renderer 仅接收可公开的应用名称和后台地址构建常量，不直接引入本地敏感 JSON。Electron 主进程保留本地配置读取，登录成功/令牌校验后在内存保存会话，账户与配置请求携带 Bearer Token，登出清除内存会话与配置。后台拥有独立 SQLite 数据库，测试另建临时数据库。

媒体工作流：用户内容 → 浏览器读取/下载 → FFmpeg 提取 → 个人对象存储与识别服务 → 文案改写 → 语音/形象服务 → 字幕/视频合成 → 用户选择的导出位置。不同路径需要不同服务，不应将“界面显示”与“生成已可用”等同。

## 配置与数据

本地 JSON、.env、进程环境变量按优先级合并。后台管理页保存的服务商配置存放在自己的 SQLite 中。根目录与后台依赖分开安装，保留两份锁文件。业务内部包名 xinyao 和原有存储约定暂不更名，以减少对既有安装的影响。

保留当前 src/electron/user-server 的职责划分，不将一次开源整理扩大为 monorepo 迁移。公开源码不依赖开发者原目录的绝对路径；运行资源导入后从当前项目目录解析。

## 已知限制

账户认证防止匿名读取，但客户端仍持有配置中的云密钥。后台不是隔离付费凭证的服务端 API 网关；不适合直接面对不受信任用户。历史代码仍有严格类型错误和未实现入口。GPU 推理、多平台打包、自动更新发行链与公开运行资源下载均需要独立验证。
